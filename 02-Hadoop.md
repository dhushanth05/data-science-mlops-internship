# Hadoop: Distributed Storage and Processing

## Introduction

As the amount of data generated by organizations grows, storing and processing everything on a single computer becomes difficult.

Companies generate large amounts of data from websites, mobile applications, banking transactions, social media, sensors, e-commerce applications, and many other sources.

When data becomes very large, we can use multiple machines and distribute the storage and processing across them.

This is the basic idea behind **Hadoop**.

```text
                 Big Data
                    |
        -------------------------
        |           |           |
     Machine 1   Machine 2   Machine 3
```

Hadoop provides a distributed approach to storing and processing large datasets.

---

# 1. Purpose of Hadoop

The main purpose of Hadoop is to **store and process large amounts of data, or Big Data, across multiple machines**.

Instead of keeping all the data in a single location, Hadoop allows us to distribute the data and processing across a cluster.

This provides two important capabilities:

- **Distributed storage**
- **Distributed processing**

For example:

```text
Large Dataset
     |
     ↓
--------------------------------
|              |               |
Machine 1    Machine 2       Machine 3
|              |               |
Data Part 1  Data Part 2    Data Part 3
```

Each machine can work with a portion of the overall data.

---

# 2. Hadoop History

Hadoop evolved from work on the **Nutch** web-search project and ideas described in Google's research on distributed file systems and MapReduce.

Doug Cutting and Mike Cafarella worked on Nutch, and the Hadoop project developed from this work in the early 2000s.

Yahoo played an important role in Hadoop's development and adoption. Hadoop became an Apache top-level project in 2008.

The important point is that Hadoop developed as an open-source approach for handling large-scale distributed data.

---

# 3. What is Hadoop?

**Hadoop** is an open-source framework and ecosystem designed to store and process very large datasets across a cluster of computers.

The main idea is:

> Instead of storing and processing everything on one machine, distribute the data and computation across multiple machines.

A simplified view of Hadoop is:

```text
                    HADOOP
                       |
       --------------------------------
       |              |               |
      HDFS           YARN          MapReduce
   Storage       Resource Mgmt     Processing
```

The three important Hadoop components are:

- **HDFS** — distributed storage
- **YARN** — resource management and scheduling
- **MapReduce** — distributed processing model

In this article, the main focus is on HDFS and MapReduce.

---

# 4. HDFS – Hadoop Distributed File System

**HDFS** stands for **Hadoop Distributed File System**.

It is the storage component of Hadoop.

The main purpose of HDFS is to store very large files across multiple machines in a Hadoop cluster.

Instead of keeping an entire large file on one machine, HDFS divides the file into blocks and distributes those blocks across different machines.

```text
              Large File
                  |
          Divide into Blocks
                  |
       -------------------------
       |           |           |
    Block 1     Block 2     Block 3
       |           |           |
   DataNode 1  DataNode 2  DataNode 3
```

This allows storage to scale across multiple machines.

---

# 5. HDFS Blocks

HDFS divides files into **blocks**.

The block size is configurable. A commonly used example is **128 MB**.

Suppose we have a 1280 MB file and use 128 MB blocks:

```text
1280 MB ÷ 128 MB = 10 blocks
```

So the file can be represented as:

```text
File
 |
 |-- Block 1
 |-- Block 2
 |-- Block 3
 |-- ...
 |-- Block 10
```

These blocks can be distributed across different DataNodes.

The important idea is:

```text
Large File
     ↓
Smaller Blocks
     ↓
Distributed across DataNodes
```

The blocks do not have to be stored entirely on one machine.

---

# 6. HDFS Architecture

HDFS mainly uses two important types of nodes:

1. **NameNode**
2. **DataNode**

The basic architecture is:

```text
                    NameNode
                   /   |   \
                  /    |    \
                 ↓     ↓     ↓
            DataNode DataNode DataNode
```

The NameNode manages the file system's metadata, while DataNodes store the actual data blocks.

---

# 7. NameNode

The **NameNode** is the main manager of the HDFS file system.

It maintains metadata about files and directories.

The metadata can include:

- Which files exist
- Which directories exist
- File and directory information
- Which blocks belong to a file
- Where blocks are stored

The NameNode does not normally store the actual user data blocks.

For example:

```text
                NameNode
                   |
          -------------------
          |        |        |
          ↓        ↓        ↓
       Block 1  Block 2  Block 3
       Location Location Location
```

The NameNode keeps track of where the blocks are located.

A simple way to remember it is:

```text
NameNode = Manager of the HDFS file system
```

---

# 8. DataNode

A **DataNode** is responsible for storing the actual HDFS data blocks.

For example:

```text
                 NameNode
                    |
       -----------------------------
       |             |             |
       ↓             ↓             ↓
   DataNode 1    DataNode 2    DataNode 3
     Block 1       Block 2       Block 3
```

The DataNodes are the machines where the actual data blocks are stored.

So:

```text
NameNode → Metadata
DataNode → Actual data blocks
```

---

# 9. HDFS Replication

One of the important features of HDFS is **replication**.

Instead of maintaining only one copy of a block, HDFS can maintain multiple copies, called replicas.

For example, if the replication factor is 3:

```text
                Block A
              /    |    \
             ↓     ↓     ↓
        DataNode1 DataNode2 DataNode3
```

If one DataNode fails, another replica of the block can still be available.

This provides **fault tolerance**.

The main idea is:

> Hadoop assumes that failures can happen, so data can be replicated across different machines.

Replication also helps improve data availability.

---

# 10. YARN

**YARN** stands for **Yet Another Resource Negotiator**.

YARN is responsible for **resource management and application scheduling** in a Hadoop cluster.

In simple terms, YARN helps applications obtain resources such as:

- CPU
- Memory

Important components include:

### ResourceManager

The **ResourceManager** manages resources at the cluster level.

### NodeManager

A **NodeManager** runs on individual worker machines and manages resources and containers on those machines.

A simple way to remember this is:

```text
ResourceManager → Cluster-level resource management

NodeManager → Resource management on an individual node
```

A simplified view is:

```text
              ResourceManager
                 /       \
                /         \
        NodeManager     NodeManager
             |               |
          Resources       Resources
```

---

# 11. MapReduce

**MapReduce** is a programming model and processing framework used by Hadoop for distributed data processing.

It follows the general idea:

```text
Input Data
    ↓
   MAP
    ↓
Shuffle / Sort
    ↓
  REDUCE
    ↓
Final Result
```

The main idea is to divide a large processing problem into smaller parts and process those parts in parallel.

For example, suppose we want to count words in a very large collection of documents.

The input data can be divided across multiple machines.

The **Map** phase processes the input and produces intermediate key-value pairs.

The intermediate data is then shuffled and grouped.

The **Reduce** phase combines the values and produces the final result.

So the general flow is:

```text
Large Data
    ↓
Divide
    ↓
Map
    ↓
Shuffle / Sort
    ↓
Reduce
    ↓
Final Result
```

---

# 12. Key-Value Pairs in MapReduce

MapReduce works with the concept of **key-value pairs**.

For example, suppose the input is:

```text
hello hello world
```

The Map phase can produce:

```text
(hello, 1)
(hello, 1)
(world, 1)
```

During shuffle and grouping:

```text
(hello, [1, 1])
(world, [1])
```

The Reduce phase can then produce:

```text
(hello, 2)
(world, 1)
```

This is a simple example of how MapReduce can process large datasets using key-value pairs.

---

# 13. Limitations of Hadoop MapReduce

MapReduce is useful for large-scale batch processing, but it has some limitations.

One important limitation is its reliance on **disk-based intermediate processing**.

When a workflow contains multiple processing steps, intermediate results may need to be written to disk and read again.

For example:

```text
Step 1
  ↓
Write intermediate data to disk
  ↓
Read data
  ↓
Step 2
  ↓
Write intermediate data to disk
  ↓
Read data
  ↓
Step 3
```

This repeated disk I/O can make certain workloads slower, especially iterative workloads where the same data is processed multiple times.

These limitations helped create demand for newer distributed processing engines such as Apache Spark.

# Key Takeaways

- Hadoop is an open-source framework and ecosystem for working with large-scale distributed data.
- HDFS is used for distributed storage.
- HDFS divides large files into blocks.
- DataNodes store the actual data blocks.
- The NameNode manages HDFS metadata.
- HDFS replication provides fault tolerance.
- YARN manages cluster resources and application scheduling.
- MapReduce is a distributed processing model.
- MapReduce uses Map and Reduce phases with an intermediate shuffle/sort step.
- MapReduce works with key-value pairs.
- MapReduce can be slower for some iterative workloads because of repeated disk-based intermediate processing.

---

# Conclusion

Hadoop provides a distributed approach to storing and processing large datasets.

The main Hadoop components are:

```text
HDFS       → Distributed Storage
YARN       → Resource Management
MapReduce  → Distributed Processing
```

HDFS stores large files by dividing them into blocks and distributing those blocks across DataNodes. The NameNode manages the metadata that describes the files, directories, and block locations. Replication helps protect data against machine failures.

YARN manages resources and schedules applications across the cluster.

MapReduce provides a distributed processing model based on Map, Shuffle/Sort, and Reduce phases.

Understanding these concepts provides a strong foundation for learning modern distributed data-processing technologies such as Apache Spark and PySpark.
